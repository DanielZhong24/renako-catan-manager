# Renako Catan Manager

Tracks Catan games played on colonist.io and reports them in Discord.

- `extension/` – Chrome extension: scrapes end-of-game stats, records the game's
  websocket traffic, and uploads both to the backend.
- `backend/` – Hono API: Discord OAuth, game storage in PostgreSQL, stats,
  leaderboards, and an admin site.
- `discord-bot/` – slash commands and match-summary announcements.
- `catan-clanker/` – optional FastAPI service that picks moves with a trained
  model, used by the extension's opt-in autoplay.

See [`architecture.md`](architecture.md) for how they fit together and each
folder's README for details.

## Container setup

Prerequisites:

- Docker Desktop with Docker Compose
- A Discord application with an OAuth2 redirect URL configured
- A Discord bot token for the bot container

1. Create the local environment file:

	```sh
	cp .env.example .env
	```

	On Windows PowerShell, use `Copy-Item .env.example .env` instead.

2. Fill in the Discord values in `.env`. The `DISCORD_AUTH_URL` and
	`REDIRECT_URI` values must use the same callback URL, and that callback URL
	must also be registered in the Discord Developer Portal.

3. Build and start the full stack:

	```sh
	docker compose up --build
	```

	This starts the API at `http://localhost:3000`, the Discord bot,
	PostgreSQL (published on host port `5433`), Redis, pgAdmin at
	`http://localhost:8080`, and the `catan-clanker` service at
	`http://localhost:8000`.

4. Build the extension for local testing and load it in Chrome:

	```sh
	cd extension
	npm install
	npm run dev
	```

	Open `chrome://extensions`, enable Developer mode, choose **Load unpacked**,
	and select `extension/dist`. Copy the extension ID into `EXTENSION_ID` in
	`.env`, then recreate the API container (`docker compose up -d api`). Use
	`/link` in Discord to connect the extension. See
	[`extension/README.md`](extension/README.md).

To record games against bots only, set `ALLOW_BOT_GAMES=true` in your local
`.env` (see below) and recreate the `api` container.

### Connecting a database client

PostgreSQL is published on host port **5433** (container port 5432), so it does
not clash with a local PostgreSQL install. Connect to `localhost:5433` with the
`DB_USER`, `DB_PASSWORD` and `DB_NAME` values (defaults `user`, `password`,
`catan_db`). The bundled pgAdmin at `http://localhost:8080` reaches the database
as host `db`, port `5432`.

To stop the containers:

```sh
docker compose down
```

To stop the containers and remove the PostgreSQL volume as well:

```sh
docker compose down -v
```

## Development containers

The development Compose file mounts the backend and bot source directories and
runs their watch scripts. Start it together with the base Compose file so the
database and Redis services are available:

```sh
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build
```

## Environment variables

Copy `.env.example` to `.env` and replace the placeholders. Do not commit `.env`
because it contains secrets.

| Variable | Required | Description |
| --- | --- | --- |
| `DISCORD_CLIENT_ID` | Yes | Discord application/client ID. |
| `DISCORD_CLIENT_SECRET` | Yes | Discord OAuth2 client secret. |
| `DISCORD_TOKEN` | Yes | Discord bot token. |
| `DISCORD_AUTH_URL` | Yes | Discord OAuth2 authorization URL for the local callback. |
| `REDIRECT_URI` | Yes | Backend OAuth2 callback URL, normally `http://localhost:3000/api/auth/callback`. |
| `API_BASE_URL` | Yes | Public API URL used in links generated by the bot. |
| `EXTENSION_ID` | No | Browser extension ID shown after successful authentication. |
| `INTERNAL_API_URL` | No | Bot-to-API URL; defaults to `http://api:3000` in Docker. |
| `BOT_INTERNAL_URL` | No | API-to-bot URL for match announcements; defaults to `http://discord-bot:3001`. Set it when the bot runs on a different host. |
| `ALLOW_BOT_GAMES` | No | Local testing only. When `true`, skips the "one human plus three or more bots" rejection. Leave unset in production. |
| `DB_USER` | No | PostgreSQL user; defaults to `user`. |
| `DB_PASSWORD` | No | PostgreSQL password; defaults to `password`. |
| `DB_NAME` | No | PostgreSQL database; defaults to `catan_db`. |
| `PGADMIN_EMAIL` | No | pgAdmin login email; defaults to `admin@admin.com`. |
| `PGADMIN_PASSWORD` | No | pgAdmin login password; defaults to `admin`. |
| `ADMIN_COOKIE_SECURE` | No | Set to `true` when serving the admin session over HTTPS. |

The backend listens on port `3000` and the bot's internal HTTP server listens
on port `3001` by default. These defaults can also be overridden with `PORT`
when running the services outside Docker.
